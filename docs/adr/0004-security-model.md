# ADR-0004: Security model

- Status: accepted
- Date: 2026-10-11

## Context

Crossfade decides which version of an app answers public traffic. Whoever controls it can point that traffic anywhere, so the control plane must be harder to reach than the apps it routes to. The video's platform made exposure an explicit, reviewable opt-in and kept tenants from routing to each other.

## Decision

- **Two origins.** The edge (Envoy, `:8080`) is public. The dashboard, CI API and xDS live on `web` at `127.0.0.1:3000` and are never routed through the edge. Dashboard cookies are issued for `BETTER_AUTH_URL` only.
- **Closed accounts.** Public sign-up is disabled. The first account is created through `POST /api/setup`, which needs a one-time token (generated by `init`, printed by `migrate`), checks the Host, accepts JSON only and is serialized by an advisory lock; it refuses once any user exists. Later accounts are created by admins.
- **Secrets as files.** `init` writes 32-byte secrets (Postgres password, xDS token, auth secret, setup token) with mode 0600 into a named volume. Nothing secret lives in the image, the compose file or git. `.env*` is excluded from the Docker build context because `next build` copies `.env` into the standalone output.
- **Envoy is authenticated.** Every xDS request must carry `node.metadata.xds_token`, compared in constant time.
- **Deny-by-default upstreams.** Versions may only point at `host:port` pairs the operator listed for that app (`UPSTREAM_ALLOWLIST`). IP literals and platform names are rejected.
- **One policy layer.** Authorization happens in the data access layer for every server action and route handler, not in `proxy.ts`.

## Consequences

- Operators who expose the dashboard beyond loopback must put an authenticating proxy in front and set `BETTER_AUTH_URL` to the public origin.
- The setup token appears in `migrate` logs until the first account exists; anyone with `docker compose logs` access already controls the host.
- Four-eyes approval (added later) stops mistakes and non-admin users, not a malicious admin.
